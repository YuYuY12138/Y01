# A03／R36 手机横屏 HUD 布局与交互说明

## 设计结论
- 本文是供审阅的布局与交互稿，不是实现计划；真实 WBP 接入仍暂停，不表示任何交互或业务已经接通。
- 手机横屏触控是用户已明确纠正并确认的确定前提，不是待定假设；不以桌面鼠标体验替代手机判断。
- 本轮只在独立目录 `UI_Deliverables/HUD_A03_R36_Design` 制作离线状态图与说明；未修改主策划、游戏 Source、Content 或配置，未进行 Git／UE 操作。
- 六张状态图是本次设计提案；未来画稿变更须同步本说明，不能把示意画面当作规则已经实现。
- 保留原有深色面板、青色强调及品质色；场景为中性背景，长段设计说明放在本文，不堆进游戏画面。
- 左侧摇杆负责移动，右下四个技能槽保持 2×2 固定位置；背包、商店、确认态不得挤走这两组操作区。
- 底部保留六个装备槽，旁边紧邻独立背包按钮；装备内容折叠后，背包按钮仍须可见、可点。
- 右侧背包为非全屏面板，四列×两行可见，每格以 112px 为制图尺寸；八格只是窗口可见数量，不是容量上限。
- 背包随物品增加自动扩展滚动内容，通过滑动查看更多格；不由此推导容量扩容、收费扩容或堆叠规则。
- 商店位于背包左侧并排展示；操作时保留背包、装备、技能目标，不以全屏商城覆盖战斗 HUD。
- 1920×1080 是制图基准，主要按钮在该基准下至少 88px 高；这些像素尺寸不等于 dp，也不代表实际手机点击面积。
- 实际逻辑触控目标计划达到至少 48dp；最终须结合 SafeZone、DPI 缩放、设备密度与真机握持验证，不能只换算截图像素。
- 各区保留三角折叠标识；三角可以视觉较小，但整个标题触控区扩大到至少 48dp，并避免与相邻按钮的热区重叠。
- 打开背包时，先记录装备区和技能区此前的折叠状态，再显式展开两区；背包操作期间不允许误折叠使目标消失。
- 关闭背包后还原装备、技能此前的折叠状态；背包独立按钮不随装备内容隐藏，各区折叠不改变固定操作位置。
- 打开面板不默认暂停战斗；不新增手动普攻按钮，也不补造未确认的资源、玩法入口或经济规则。
- 主动技能用“释放／冷却中”等状态表达可操作性，被动技能明确标“被动／生效中”，不伪装成可释放按钮。
- 图中两主动、两被动仅是状态示例，不据此规定技能配比；展示名称、数值、倒计时也不构成正式配置承诺。
- 来源沿用旧包 PNG；新增基础装备与技能书是自制几何占位，不冒充具体装备美术，不据几何外形新增装备限制。
- Microsoft YaHei 仅用于本机预览渲染，不打包分发字体；沿用来源记录，不额外宣称服务适用条款、授权范围或排他权。

## 手机手势
- 手机不设计 hover；旧素材即使使用悬停态样式，也只可借作选中／按下强调，不要求鼠标悬停才出现信息。
- 普通点击用于查看物品详情；技能释放属于明确的主动技能操作，不能把物品点击解释为自动穿戴或学习。
- 按住物品后，在小幅移动容差内等待长按触发拖动；长按阈值、移动容差及拖影偏移量均留待实机调校。
- 未到长按阈值时，符合滚动意图的移动优先交给背包滚动；滚动一旦成立，立即取消候选长按。
- 已取消候选长按的本次手势不能继续转成穿戴或学习；滚动结束的松手也不能误判为点击物品或投放。
- 长按成立后进入拖动，来源格保留占位与状态，拖影偏到指尖上方，让手指不遮住物品和接收目标。
- 只有程序返回的合法目标高亮；非法目标保留可辨别的拒绝反馈，不能仅凭物品图标外观猜测可投放性。
- 拖动指针与移动指针隔离；拖动手势不能接管左摇杆，左拇指移动尽量不中断，但仍须真机验证。
- 单个右拇指正在拖动时，不能同时用该手指施法；固定技能位置不是“同指可同时拖放和释放”的承诺。
- 拖影经过技能按钮或松手投放时不透传施法；即使目标合法，也只解释为本次物品投放，而非点击释放。
- 靠近滚动区边缘自动滚动仅为提案，不列为已确定交互；边缘范围、速度、误触抑制须另行确认。
- 点击详情的位置必须避开背包／装备／技能接收区；开始拖动时收起或让开详情，不能让说明卡挡住目标。
- 标题整区承接折叠点击，三角只作方向提示；背包操作期间装备、技能的折叠入口不能造成目标突然消失。
- 管理入口与释放入口分离：管理→选择技能→移除→二次确认；选择管理对象不触发技能释放。
- 被动技能不响应释放手势；其详情及移除仍从明确的详情／管理路径进入，不靠长按释放按钮兼任删除。
- 确认层不默认暂停、不吞掉无关左侧移动触点；具体多指分发与遮挡范围以 SafeZone／DPI 真机验证为准。

## 操作状态机
### 通用状态与权威结果
- 空闲→按下候选：记录本次物品来源与触点；短按完成进入详情，未产生任何穿戴、学习或消耗请求。
- 按下候选→滚动：识别滚动后取消长按候选；本次松手只结束滚动，不生成物品业务请求。
- 按下候选→拖动：长按成立并满足容差条件后出现拖影，展示程序返回的合法目标；来源仍未被消耗。
- 拖动→非法松手：拖影回原位、清理高亮；不调用业务，不扣除物品，不触发下层技能。
- 拖动→合法松手：依操作进入请求待决或覆盖确认；仅显示待处理，不提前把来源、装备或技能改成成功结果。
- 确认待选择→取消：恢复确认前展示，来源与旧目标不变，无消耗；确认学习才进入请求待决。
- 请求待决：只锁关联物品、关联目标及提交按钮，防重复提交；不冻结全屏，不连带禁用无关移动和操作。
- 权威成功→结果反馈：按返回状态更新来源、目标及相关数值，再显示实际接收格、成功提示或品质反馈。
- 权威拒绝／源槽变化→重同步：以最新权威状态重绘并给出简短原因，不强塞旧结果，不伪造成功或静默扣除。
- 若权威状态已变化，“回原位”只表示取消拖影，不强行恢复失效快照；待决中的扣款、消耗、授予事务由程序实现。
- 界面只负责请求意图和反馈，不另做一份结算；内部 ID 不向玩家展示，合法性与实际接收位置均按程序返回。
### 装备穿戴、替换与卸下
- 背包装备→合法空装备槽：请求穿戴，权威成功后才将来源与装备槽更新到新状态。
- 背包装备→合法占用装备槽：请求替换，权威成功后新装备入槽、旧装备回包，并标明实际接收位置。
- 已穿装备→合法背包接收区：请求卸下，成功后回包；实例与成长等数据保留由程序负责，界面不重建装备实例。
### 技能书学习、覆盖与移除
- 技能书→合法空技能槽：请求学习，成功才学习该技能并消耗一本；失败或拒绝不作本地先扣再补的假成功。
- 技能书→合法占用技能槽：进入覆盖确认，明确展示新旧技能及“消耗一本技能书，旧技能不返还”。
- 取消覆盖无消耗、旧技能不变；确认后仍须等待权威成功，才消耗一本技能书并更新该技能槽。
- CD 中允许学习覆盖；不在本文定义新技能初始 CD、继承 CD 或刷新 CD，不能从示意倒计时推导这些规则。
- 已学技能不可拖回背包，也不还原为技能书；管理路径中的移除须二次提示“移除后不返还技能书”。
- 移除确认与释放按钮分离，取消不移除；提交后只按权威成功结果更新技能槽，不提前清空。
### 商店、掉落与到账反馈
- 商店固定三类：随机装备、随机技能书、直接属性；价格、档位和效果读配置，不在稿中创造售价或效果数值。
- 随机装备购买成功后入包、不自动穿戴；随机技能书入包、不自动学习；直接属性由权威结果直接生效。
- 购买待决只锁关联购买按钮及相关对象；权威拒绝重同步，不显示成功回执；成功购买没有撤销入口。
- 背包打开时闪亮实际接收格；背包收起时在独立按钮标“新”，不因到账自动弹包或抢占当前操作。
- 金币、经验到账数字以及消费后的余额展示权威值，不按动画次数或本地价格再做一次加减结算。
- 掉落仅表现为无碰撞地飞向角色；视觉到达配合唯一权威交付后，才闪亮实际接收格，不让粒子决定发奖。
- 动画先到而权威结果未到时，不预报入包；权威先到也不因后续动画到达再发一次奖励或重复记账。
- 新物品接收格在滚动屏外时，给包内未读定位提示，允许玩家主动定位，不强跳滚动抢走正在看的内容。
### 五合一选择与结果
- 从背包选择同类型、同品质的五份材料；同类型内允许不同名字混合，装备与技能书分开，不能混成一组。
- 已穿装备须先卸下才可作为材料；已学技能不参与；红色为最高品质，不提供红色再升级的入口。
- 材料是否有效以程序返回为准；不足五份、混类型、混品质等不合法选择不能被表现为可提交成功。首份锁定本组类型与品质，选满五份后不再追加；点已选材料可取消选择，再换材料。
- 「退出合成」只退出选择模式，不消耗材料；不能把它当成合成成功后的撤销。
- 预览只显示高一级目标品质和随机结果，不提前展示确定成品；权威成功后才消耗五份并把结果放回背包。
- 合成费用与材料成长继承均待定；不得显示“0费／免费”，不得把界面示意当成未确认支付的许可。
- 如后续进入已确认规则下的请求待决，仅锁这五份材料及关联合成按钮；当前稿不承诺真实合成可执行。

## 待决及验收口径
- 已确认：手机横屏、六装备、四主动／被动共用技能槽、自动扩展背包、战斗中操作与本次用户列明的业务边界。
- 待审阅的布局提案：四列背包置右、商店置其左侧、八格可见窗口、背包打开期间固定展开装备／技能，以及沿用左移动右技能的相对位置。
- 待决：合成费用、成长继承、新技能初始 CD、长按阈值与移动容差、拖影偏移、边缘自动滚动是否采用。
- 待决：具体机型、SafeZone、DPI 和多指手势表现，以及死亡、断线、结束经营时如何处理面板与未完操作。
- 首版不画地面物品、拾取、丢弃、交易、赠送、容量扩容、还原技能书、出售或回购入口。
- 静态审阅关注各状态布局关系与文案；动态交互、程序合法性、事务一致性和真实到账须独立验证，不能从图面认定通过。

- 静态计时值仅示意；倒计时终点和语义按程序阶段接口确定，不新增战斗限时失败规则。
